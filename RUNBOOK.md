# GvardPay — полный пайплайн запуска с локальным валидатором

Три независимых процесса, которые должны работать одновременно:
**solana-test-validator** (своя блокчейн-нода) + **Metro/Expo** (dev-сервер
приложения) + **телефон** (Expo Go или dev-client). Они не запускают друг
друга — каждый стартуется отдельно, руками.

---

## Шаг 0. Применить фиксы (один раз)

1. Распакуй `gvardpay-fixes.zip` поверх папки `gvardpay/gvardpay` (`node_modules` в архиве нет специально).
2. В этой папке:
   ```
   npm install
   cp .env.example .env
   ```
3. Открой `.env` — пока оставь как есть, IP впишем в шаге 3, когда узнаем его для конкретной сети.

Без `npm install` фикс с `react-native-get-random-values` не подтянется, и кошелёк снова не будет создаваться — это отдельный шаг, не часть распаковки архива.

## Шаг 1. Установить инструменты

### macOS

| Инструмент | Команда |
|---|---|
| Node.js 20 LTS | `brew install node@20` (или установщик с nodejs.org) |
| Solana CLI | `sh -c "$(curl -sSfL https://release.anza.xyz/stable/install)"` |
| Xcode *(нужен только для симулятора/сборки на реальный iPhone)* | App Store, долгая установка |

После установки Solana CLI — новый терминал, проверить: `solana --version`.

> Эту конкретную команду для установки Solana CLI я не могу проверить вживую из песочницы (нет доступа к `release.anza.xyz` оттуда, где я работаю) — она собрана по памяти на основе того, как это долгое время документировалось. Если не сработает — поищи "install solana cli mac", первая ссылка на docs.anza.xyz будет с актуальной командой.

### Windows

| Инструмент | Команда |
|---|---|
| Node.js 20 LTS | установщик с nodejs.org |
| Solana CLI | см. ниже — два варианта |
| Android Studio *(нужен только для эмулятора/сборки на Android)* | developer.android.com |

**Вариант A — нативно на Windows (проще для этой задачи):**
```
cmd /c "curl https://release.anza.xyz/stable/solana-install-init-x86_64-pc-windows-msvc.exe --output C:\solana-install-tmp\solana-install-init.exe --create-dirs"
C:\solana-install-tmp\solana-install-init.exe stable
```
Закрыть и открыть терминал заново, проверить `solana --version`.

**Вариант B — через WSL2 (Ubuntu):** та же команда, что и для macOS/Linux, внутри WSL. Дальше валидатор будет слушать внутри виртуальной сети WSL, а не напрямую на Wi-Fi адаптере Windows — с телефона он просто так не достучится. Нужен дополнительный проброс порта:
```
netsh interface portproxy add v4tov4 listenport=8899 listenaddress=0.0.0.0 connectport=8899 connectaddress=<IP WSL, узнать через `wsl hostname -I`>
```
Если это звучит как лишняя головная боль — так и есть, поэтому для этой конкретной задачи вариант A практичнее.

> Как и для macOS, команду нативного Windows-инсталлятора я не смог проверить вживую (тот же вопрос с доступом к `release.anza.xyz`) — собрана по памяти, это самый неточный пункт во всей инструкции. Если `solana-install-init.exe` не скачается по этой ссылке — тот же поиск "install solana cli windows" на docs.anza.xyz.

## Шаг 2. Узнать IP машины и прописать в `.env`

Нужен LAN-адрес компьютера, на котором будет крутиться валидатор — телефон стучится именно на него, не на `localhost`.

- **macOS:** `ipconfig getifaddr en0` (Wi-Fi). Если пусто — `ipconfig getifaddr en1`.
- **Windows:** `ipconfig`, смотреть строку **IPv4-адрес** под активным адаптером (обычно "Беспроводная сеть" / Wi-Fi).

Вписать в `.env`:
```
EXPO_PUBLIC_LOCAL_RPC_URL=http://<этот-IP>:8899
```

Важно: этот IP меняется при смене Wi-Fi сети (дом/офис/кафе) — придётся обновлять `.env` и перезапускать `npx expo start` каждый раз при смене сети.

Если тестируешь в симуляторе/эмуляторе (не на реальном телефоне) — можно оставить `127.0.0.1`, он даёт корректный доступ и на macOS (iOS-симулятор), и на Windows (Android-эмулятор), так как они делят сеть с хостом.

## Шаг 3. Запуск (каждый раз)

**Терминал 1 — валидатор** (одинаково на macOS и Windows):
```
solana-test-validator --bind-address 0.0.0.0
```
Оставить открытым на всё время работы. При первом запуске система спросит разрешение на входящие соединения (Firewall на macOS / Защитник Windows на Windows) — обязательно разрешить, иначе телефон не достучится.

Ledger сохраняется в папке `test-ledger/` там, откуда запущена команда — состояние переживает перезапуск, если запускаешь из той же папки. Нужен чистый лист — добавь флаг `-r`.

**Терминал 2 — Expo** (одинаково на обеих ОС):
```
cd gvardpay/gvardpay
npx expo start
```

**На телефоне:** открыть приложение (через Expo Go или собранный dev-client — см. предыдущий фикс про несовпадение SDK, если Expo Go ругается на версию), затем в самом приложении — **Настройки → Сеть → Localnet**.

## Тестирование: что доступно на какой ОС

| | macOS | Windows |
|---|---|---|
| Физический iPhone (Expo Go / dev-client по Wi-Fi) | ✅ | ✅ |
| Физический Android (Expo Go / dev-client по Wi-Fi) | ✅ | ✅ |
| iOS-симулятор | ✅ (нужен Xcode) | ❌ невозможно в принципе — Apple не даёт запускать iOS-рантайм вне macOS |
| Android-эмулятор | ✅ (Android Studio) | ✅ (Android Studio) |
| `npx expo run:ios` (нативная сборка) | ✅ | ❌ |
| `npx expo run:android` | ✅ | ✅ |

То есть если основная машина — Windows, самый прямой путь потестировать на iPhone — это физическое устройство по Wi-Fi через Expo Go/dev-client, симулятора не будет никогда.

## Быстрый чек-лист при проблемах

- **Приложение не видит валидатор / зависает на загрузке баланса** — проверь, что `.env` содержит актуальный IP (не `localhost`, если тестируешь на реальном телефоне), что валидатор запущен с `--bind-address 0.0.0.0`, и что телефон и компьютер в одной Wi-Fi сети.
- **Firewall/Defender молча блокирует** — переустановка правила: удали приложение "solana-test-validator" из списка разрешённых и разреши заново при следующем запросе.
- **Expo Go ругается на версию SDK** — это отдельная история (несовпадение SDK проекта и версии Expo Go в App Store/Play Store), локального валидатора не касается. Решение — dev-client, см. предыдущий разбор.
- **После смены Wi-Fi всё перестало работать** — IP из шага 2 устарел, обнови `.env`, перезапусти `npx expo start`.
